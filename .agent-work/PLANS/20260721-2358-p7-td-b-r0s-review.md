## 4. Planner 复验发现

以下不是对 R0S 离线交付的否决；它们是进入实机前必须在下一工作包闭合的 production 边界。

### R0S-PR-001：Setup 函数未接入正式 CLI

`execute_td_b_exposure_setup()` 只被测试直接调用。正式 `main()` 仍执行：

```text
build unresolved plan -> validate_authorized_execution_plan -> fail
```

CLI 没有 setup phase、setup artifact 参数或 resolve/resume 分支，现有 wrapper 也没有调用 setup。

### R0S-PR-002：Canonical cleanup 存在时序所有权缺口

成功 setup artifact 要求 shell cleanup 和 wrapper exit evidence，但这些证据只有 child 退出后才由
wrapper 产生。当前函数要求 caller 预先注入 `shell_cleanup_evidence`，这在 fake 测试成立，在真实 child
内不能成立。需要 provisional capture evidence 与 wrapper 后置 canonical finalization 两阶段所有权。

### R0S-PR-003：通用 auto-exposure 不满足 retained-v2 attempt 合同

现有 `camera_gphoto2.auto_expose_capture()` 默认通过 backend `capture()`，即 remote `/v1/capture`；它还
删除 trial/rejected-final RAW。R0S 正式 schema 要求每个 1..8 physical attempt 保留 CR3 和 v2 sidecar。
下一包必须复用现有曝光搜索决策，但通过窄的 retained-v2 capture hook 保留每次 attempt；不得复制一套
曝光搜索算法。

### R0S-PR-004：首次 capture 前尚未验证 active-source isolation

当前 injected state machine 在调用 capture setup 之前收集 Ray set/readback 和 strip-zero evidence，
但 exact HSI/readback/generation validator 只在最终 artifact 构建时运行。真实路径必须在第一张 CR3 前
就验证这些证据，错误状态不能先拍后拒绝。

### R0S-PR-005：Checkpoint/plan/wrapper 绑定仍不足以执行

非 fake setup 目前只要求 `code_checkpoint` 是 40 位小写 hash，没有把它与当前 HEAD、unresolved plan、
wrapper hash、resolved plan 和 formal run 同一绑定。下一包必须冻结并独立重放这些关联。
