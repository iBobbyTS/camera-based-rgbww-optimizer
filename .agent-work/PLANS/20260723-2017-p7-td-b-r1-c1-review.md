## 4. Planner Findings

### REV-C1-001 - Must Fix / Agent-Fixable

**触发：** sidecar 通过 `is_file()`/`stat()` 检查后，在 `_validate_returned_sidecar()` 的
`read_bytes()` 前消失或发生读取 `OSError`。

**证据：** `src/camera_based_rgbww_optimizer/optimization/measure_p7_thermal_diagnostics.py` 当前只在 JSON/parser
阶段捕获 `UnicodeError`、`JSONDecodeError` 和 `RemoteCaptureV2Error`；sidecar `stat/read_bytes` 的 `OSError`
在 physical ledger row 写入前逃逸。Planner 使用受控 monkeypatch 令 sidecar `read_bytes()` 抛出
`FileNotFoundError`，观察到：

```text
physical_returned_cr3_count = 0
physical_cr3_count = 0
physical-returns.jsonl = absent
rejected_capture.cr3_sha256 = null
rejected_capture.sidecar_validation_status = pending
```

**影响：** adapter 已返回非空 CR3，但 sidecar 缺失/读取竞争路径会丢失 physical accounting 和 CR3 hash，违反
C1 的核心 fail-closed evidence contract，并可能让后续预算/forensic replay少计实际物理快门。

**最小修复方向：** sidecar 路径、stat、read、decode、schema 与 payload validation 的所有预期文件系统失败都必须
转成携带 evidence 的 `_SidecarAssociationError`；无论 sidecar validation 成败，只要 current-run CR3 已被验证，
必须先/最终写入唯一 physical ledger row 并更新 physical count，然后抛出 rejection。新增 deterministic
post-stat read failure 与 sidecar replacement/removal tests。

### REV-C1-002 - Must Fix / Agent-Fixable

**触发：** 落盘 sidecar 本身通过 remote-v2/CR3 validation，但 adapter 返回的内存 `timing_metadata` 或
`timing_evidence` 与 sidecar 不一致。

**证据：** `_validate_returned_sidecar()` 已成功取得 `remote_metadata` 和 receipt 后才检查 adapter copy；发生不一致
时 exception evidence 不携带刚验证的 remote IDs，caller 因此将 ledger 与 failure payload 的
`remote_capture_id`/`remote_request_id` 写为 `null`。Planner 受控复现得到 sidecar hash 非空，但四个 remote ID
字段均为 `null`。

**影响：** 对一个密码学绑定 CR3 且结构有效的 sidecar，已验证 remote owner 被丢弃，违反 docs/skill/C1 对
physical ledger 与 rejection payload 保留 capture/request IDs 的明确合同，降低跨 ledger forensic 关联能力。

**最小修复方向：** 在 sidecar remote-v2 validation 成功后立即把 capture/request IDs 纳入 helper evidence；随后
adapter copy mismatch 仍 fail closed，但 physical ledger 和 rejection payload 必须保留 sidecar 中已验证的 IDs。
对 `timing_metadata` drift 与 `timing_evidence` drift 分别加回归。
