## 1. 修复目标

TD-A 第一次离线进入检查发现两个已知必败条件：TD-B-only 的 `ray-h120-s50` 污染 TD-A
shutter ledger，以及 production runner 会向 remote `/v2/capture` 发送 `iso:null`、
`aperture:null`。R0D 只修复这两个进入条件，不改变任何实机授权范围。

## 2. 已接受实现

- shutter ledger 由当前 experiment/source 的 capture steps 反推；TD-A Ray 仅包含
  `ray-h120-s100=1/5000`，TD-A strip 仅包含
  `strip-h120-s100-fullscale=1/320`。
- 两个 TD-A plan 的 `exposure_setup_required=[]`，不包含 `ray-h120-s50`；未来 TD-B Ray
  仍保留该缺失 shutter 的显式 setup 语义。
- authorized runner 在 backend connect 后、任何灯光和 capture 前，只调用一次
  `resolve_capture_settings(iso=None, aperture=None, image_format="RAW")`。
- 解析后的非空 ISO、aperture 和 RAW 字符串注入 ambient、fixed cached 与 timed capture；
  timed cycle 继续使用 retained shutter，且不允许 auto-exposure。
- plan/run/capture settings provenance 由 public analyzer 逐层重放；空值、non-RAW、choice
  mismatch、shutter 缺失/污染和 provenance 篡改均 fail closed。
- wrapper 可在启动 child 前创建仅用于 shell cleanup/exit evidence 的目录；settings 解析失败时，
  Python acquisition layer 不得创建 `plan.json`、`run.json`、capture 或灯光副作用。该目录所有权
  不构成一次 TD-A acquisition。
