**配套决策：** `3.GUIDE.md`

## 0. 结论摘要

### 0.1 P7-R1 不返工，但不能继续进入 sentinel

P7-R1 的采集、命令读回、光源隔离、CR3、预算账本和双 cleanup 都有完整证据；失败发生在冻结的 reference/repeatability stability gate，而不是 capture corruption。它应保留为一次高价值的**非平稳性证据**，不重跑、不删首帧、不改阈值，也不把失败改写成物理 gamut。

当前最重要的新事实是：

```text
off 1 s -> on 60 s -> capture -> off
```

并没有定义出一个对 Ray 和 strip 都可复现的统一状态。它既不是真正 cold-start，也没有被证明是 steady-state；它更准确的名称是：

```text
short-off / 60 s transient protocol
```

### 0.2 正式产品标定采用 steady-state；cold 60 s 作为独立启动包络

本轮决定采用两个明确分离的 operating envelope：

1. **主标定包络：** `conditioned_steady_after_switch`  
   光源持续工作或从可复现的预热状态切换命令，等待实测得到的 `t_formal` 后比较 Ray 与 strip。P7 的 `faithful`、后续 gamut、holdout 和产品 LUT 均以此为主。
2. **次级启动包络：** `emitter_cold_t60`  
   发光引擎经过长时间熄灭并达到 cold proxy 后，从目标命令启动，在 60 秒采集。它只用于报告 startup 是否也被同一命令覆盖，不与 steady 数据合并估计中心或 covariance。

若同一命令同时通过两个包络，可声明 `steady_and_startup60_qualified`。若只通过 steady，则状态是：

```text
faithful_steady = true
startup_60s_status = transient_mismatch | unqualified
```

本轮不建立第二套 startup LUT，也不引入按时间变化的运行时补偿。

### 0.3 下一轮不是 ABBA 长跑，而是三阶段热态辨识

下一轮限定为：

```text
TD-A cold settling
-> TD-B conditioned command-switch/history
-> TD-C balanced cross-session Ray/strip comparison
-> Advisor review
```

经典 ABBA 暂不批准为主方案。ABBA 只对**共同、近似线性、时间间隔规则**的漂移有消除意义；当前 Ray 与 strip 的源内热漂移不同，而且切换光源会改变各自热历史，违反关键假设。当前更合适的是跨独立 session 平衡 `Ray->strip` 与 `strip->Ray` 顺序，并直接检验 order effect。

### 0.4 thermal/time covariate 允许且必须记录，但不得吸收失败

允许加入 `time_since_on`、`time_since_command_change`、previous state、off duration、load-history proxy、ambient/surface temperature 等 influence quantities，用途仅限：

- 定义 operating envelope；
- 诊断 settling 与 history dependence；
- 估计同一包络内的 conditional repeatability；
- 为未来独立验证的 correction model 留证据。

禁止：

- 把可预测的单向漂移直接塞进 repeatability covariance；
- 用扩大 uncertainty 的方式把 trend failure 改成通过；
- 在同一 run 中拟合 thermal correction、再用同一数据验收；
- 使用运行时不可观测的 covariate 构造产品补偿。

### 0.5 `reference_epoch_shift=false` 当前应解释为“不可辨识”，不是“没有漂移”

P7-R1 的 Ray 当前中心对 P6 compatibility gate 失败，同时当前会话内部也不稳定。因此，稳定的跨 epoch 中心差尚不可估计。当前正确语义为：

```text
reference_stationarity = fail
raw_p6_compatibility_gate = fail
interpretable_p6_compatibility = not_evaluable
reference_epoch_shift_status = not_identifiable_due_to_within_run_nonstationarity
legacy_reference_epoch_shift = false
```

只有在同一 operating envelope 下先证明 current-session Ray 稳定，才可判断：无 shift、共同 shift、state-dependent shift，或仅仅是 operating-envelope mismatch。

## 2. P7-R1 到底证明了什么

## 2.1 已证明：采集链与 fail-closed 机制工作

P7-R1 完成：

```text
82 logical / 80 formal / 105 physical CR3
30 Ray / 50 strip / 2 ambient formal sources
0 weak reacquire
82 retained selected CR3, all non-empty
0 retained .npy
```

命令/readback、source isolation、capture ownership、physical ledger、recorded exposure、Python cleanup、shell cleanup 和 wrapper exit 均可复核。因此该 run 不是无效数据，也不需要因数值失败整体返工。

## 2.2 已证明：当前 1 s off / 60 s on 协议未产生稳定 reference

三个 Ray state 的当前中心相对 P6 与当前 A/B repeatability 均越过冻结 gate：

| Ray state | 当前中心 vs P6 | 当前 A/B repeatability |
| --- | ---: | ---: |
| H0/S0 | `51.97 > 9.51` | `139.46 > 9.50` |
| H120/S100 | `29.25 > 9.48` | `96.09 > 9.50` |
| H300/S100 | `17.81 > 9.63` | `14.35 > 9.63` |

H120/S100 与 H300/S100 的 Ray B 首帧还有 `0.5633`、`0.7435` single-frame dominance；所有 strip command 也处于 `uncertainty_unresolved`。这足以拒绝“当前 60 秒 protocol 已经稳定”的假设。

## 2.3 未证明：是 Ray 变了、相机变了，还是协议错了

当前 chronology 为：

```text
ambient -> Ray A -> strip A -> strip B -> Ray B -> ambient
```

Ray A 与 Ray B 之间隔着约 50 分钟 strip 高输出。这个顺序同时混合了：

- Ray 长时间熄灭后再次启动；
- strip 长时间高负载；
- 相机、环境和几何随 session 时间变化；
- 不同目标的 previous-state history；
- 1 秒 off 无法复位的余热。

所以 current center vs P6 failure 与 current A/B failure 不能被同一个布尔值概括。最严格的结论仍是：

> 当前参考/被测光源的 operating state 未被现有协议定义为稳定且可比较。

## 2.4 Synthetic joint coverage 通过不能覆盖真实 trend failure

上一轮 uncertainty artifact 和 Monte Carlo 传播回答的是：在已冻结的随机/模型不确定度假设下，null pair 的 Hue/SAT/shape 应如何分布。P7-R1 的 chronology trend 是未被该随机模型覆盖的系统性影响。二者不矛盾：

```text
uncertainty propagation implementation = working
measurement process stationarity = failed
```

正确处理是改进 measurand/operating-condition 定义，而不是扩大 joint coverage。

## 3. 首要问题不是“等多久”，而是“要复制哪个状态”

## 3.1 measurand 必须包含 operating envelope

本项目的 measurand 不能只写成：

```text
Ray H/S/INT100 对应的 58-feature color direction
```

还必须包含：

```text
source thermal/history state
command dwell time
previous state/load
ambient range
fan/power mode
```

同一命令在不同时间与热历史下若产生不同 feature center，它们是不同条件下的 measurand realization，不能全部压进一个 repeatability distribution。

JCGM 的 steady-state operating condition 强调校准关系在所定义条件下仍保持有效；rated/reference conditions 也应明确 measurand 与 influence quantity 的范围。对本项目而言，这直接要求把 settle protocol 写进 `faithful_scope`，而不是只写一个裸 `60 s`。

## 3.2 “off 1 秒”只重发命令，不等于冷却复位

1 秒足以：

- 证明命令从全零重新进入目标；
- 发现 stale command、readback 或控制链错误；
- 模拟短暂熄灭后重新点亮。

但它不足以证明：

- LED junction、基板、灯体、驱动器回到环境温度；
- Ray 与 strip 回到相同热历史；
- 前一 command 的通道负载影响已消失；
- 60 秒之后已进入平台。

因此上一轮的 independent off/on confirmation 仍有工程价值，但不再可被自动命名为 cold-start repeatability。

## 3.3 cold-start 也必须精确定义

本轮使用的 cold 是**发光引擎 cold proxy**，不是未经证明的 mains power-cycle：

```text
Ray: INT=0, emitter off
strip: all five channels = 0
```

优先定义：

```text
off until source surface/heat-sink temperature is within 1.0 °C of ambient
and absolute temperature slope <= 0.1 °C/min over 5 min
```

若没有温度传感器，只允许使用：

```text
off >= 30 min; continue to 45/60 min if previous high-load run was long
ambient stable within predeclared range
label = cold_proxy_uninstrumented
```

固定 off 分钟数只是代理，不能写成已测得的 junction-temperature equilibrium。

## 3.4 steady-state 不等于固定分钟数

应由输出稳定性选择最短有效 `t_formal`，不是先规定 60、300 或 600。DOE/PNNL 对可调 LED 产品的测试也采用先初始稳定，再根据输出变化率决定后续点的稳定时间；该报告的具体 `0.5%/30 min` 是其光度测试标准，不直接移植为本项目颜色 gate，但方法论支持“按实测稳定性决定 dwell time”，而不是假设每个状态都有相同固定 warmup。

本项目只在冻结的 58-feature 与现有 joint gate 中判定稳定，不新增光通量阈值。

## 4. 正式 operating envelope 决策

## 4.1 主包络：conditioned steady after switch

定义：

1. 光源已完成 source-specific initial warmup；
2. 切换到目标 command；
3. 等待 `t_formal`；
4. 在 `t_formal..600 s` 的后续观测中，没有超出冻结 stability gate 的持续趋势；
5. previous-state 对返回 anchor 的 center 不产生可分辨偏移。

主包络对应摄影灯的典型使用：灯具先开启，随后调色并拍摄。它也是构建稳定 LUT 最合理的基准。

## 4.2 次包络：emitter-cold at 60 seconds

定义：

1. source 满足 cold proxy；
2. 直接切到目标 command；
3. 在 exposure start 的 `60 s` 采集；
4. 不把 60 s 帧与 steady 帧合并。

需要保存：


the source-internal startup shift:

\[
\Delta f_{startup,s,q}=f_{s,q}(60)-f_{s,q}(t_{formal})
\]

以及同一目标的 cross-source startup mismatch：

\[
\Delta f_{R-S,q}^{60}=f_{strip,q}(60)-f_{Ray,q}(60)
\]

如果两个 source 的 transient 恰好同方向、同幅度，同一命令可能同时覆盖 startup 与 steady；这必须由数据证明，不能假设。

## 4.3 为什么不把两个 envelope 合并为 worst-case uncertainty

将 cold60 与 steady 的中心差直接加入一个宽 covariance 会产生反直觉结果：漂移越大，验收范围越宽。正确分解是：

\[
\Sigma_{within\ envelope}=\Sigma_{conditional}
\]

\[
\Delta_{between\ envelopes}=\mu_{cold60}-\mu_{steady}
\]

前者是重复性；后者是 operating-condition effect。只有前者进入该 envelope 的 uncertainty artifact，后者作为单独规格/状态报告。

## 5. 下一轮诊断的研究设计

## 5.1 总体原则

下一轮只回答四个问题：

1. 从 emitter-cold 到 60/120/300/600 秒，Ray 与 strip 各自如何变化？
2. 在已预热条件下，从不同 command 切换后是否收敛到同一 center？
3. previous state 是否留下超过 gate 的 history/hysteresis？
4. 当 source state 已标准化后，当前 Ray steady center 是否仍与 P6 不兼容？

不优化命令，不改 candidate，不进入 sentinel。

## 5.2 TD-A：cold settling curve

### 目标状态

```text
Ray: H120/S100/INT100
strip: retained P7-R1 H120/S100 command
```

选择 H120/S100 的原因：

- 是四点 sentinel 的稳定高饱和控制点；
- P7-R1 当前 center 与 A/B repeatability 都显著失败；
- Ray 与 strip 都有直接对应状态；
- 输出高，能较快暴露 thermal settling。

### 采样

每个 source 独立进行 3 个 cold cycle：

```text
cold proxy
-> target on continuously
-> capture at 60, 120, 300, 600 s
-> off and re-cool
```

总 formal captures：

```text
2 sources x 3 cycles x 4 times = 24
```

不得在 60/120/300/600 之间关灯或重发零命令。auto-exposure 必须在该 cycle 前冻结；timed cycle 内不得插入 trial capture。

### `t_formal` 判定

对每个 source 先求最早的 `t_settle_source`：

- 该时间及所有更晚时间的 pairwise difference 均处于冻结 same-state joint coverage；
- pooled chronology trend 不超过现有 `4.0`；
- single-frame dominance 不超过现有 `0.5`；
- 3 个 cold cycle 的最终 center 兼容；
- 没有同方向的剩余单调漂移。

然后：

\[
t_{formal}=\max(t_{settle,Ray},t_{settle,strip})
\]

注意：`600 s` 是本轮诊断上限，不是自动可接受的 steady 点。如果到 300→600 仍有趋势，状态是：

```text
not_settled_by_600
```

需要另行申请 900/1200 秒 extension；不能只因 600 是最后一帧就宣布稳定。

## 5.3 TD-B：conditioned command-switch 与 history

### 固定 reference state

```text
A = H120/S100
```

对每个 source 单独运行。先把 A 保持到 600 秒，采一个初始 A reference。随后依次测试：

```text
D = H120/S50   # same hue, different RGB/WW/CW participation
B = H0/S0      # white-heavy / SAT0
C = H300/S100  # high-curvature stress state
```

strip 使用 P7-R1 retained commands；Ray 使用对应 HSI command。禁止在该诊断中修改命令。

### 顺序

```text
A settled
-> D captures at 60/120/300/600
-> A return at t_formal
-> B captures at 60/120/300/600
-> A return at t_formal
-> C captures at 60/120/300/600
-> A return at t_formal
```

每 source formal captures：

```text
1 initial A + 3 x 4 target captures + 3 A returns = 16
```

两 source 共 32。

### 判定

- D/B/C 各自必须在 `t_formal` 及更晚点保持稳定；
- 三个 return-to-A center 必须与 initial A 以及彼此兼容；
- 若 return-to-A 随 previous state 系统性分裂，标记：

```text
history_dependent_at_current_protocol
```

- 若不同 state 需要不同 settle time，则 `t_formal` 更新为所有已测 source/state 的最大稳定时间；
- 若任何 state 到 600 秒仍不稳定，停止，不进入 TD-C。

## 5.4 为什么经典 ABBA 暂不批准

NIST 的 drift-eliminating comparison design 要求：

- 漂移在设计时间窗内可近似线性；
- measurement duration 近似相同；
- observation interval 规则；
- 被比较对象的 thermal handling 尽量相同。

当前系统必须 Ray/strip 分时点亮，而且一个 source 被关闭时会改变自己的热状态。于是：

```text
common camera/environment drift
+
source-specific thermal drift
+
state-history effect
```

被同时混入。ABBA 只能平衡第一项，不能消除后两项；更糟的是，若把 source-specific drift误当 common drift，会得到过于乐观的差值。

因此本轮决定：

```text
classic_ABBA = deferred
```

只有 TD-A/TD-B 已证明 source state 可标准化，且 Planner 能把四次 observation 控制在经实测近似线性的短时间窗、规则间隔内，才可另行申请 ABBA mini-run。

## 5.5 TD-C：balanced cross-session comparison

当前批准的替代方案是独立 session 内配对、跨 session 平衡顺序。

### Core state

```text
H120/S100
```

四个独立 comparison session：

```text
session 1: Ray -> strip
session 2: strip -> Ray
session 3: Ray -> strip
session 4: strip -> Ray
```

每个 observation 都使用 TD-A/TD-B 冻结的 cold/conditioned procedure，并在 `t_formal` 采集；session 开始时两 source 都必须处于规定的 cold proxy。每个 session 记录 start/end ambient diagnostic。

Core formal captures：

```text
4 sessions x 2 sources = 8
```

分析以 session 内差值为主：

\[
d_j=f_{strip,j}-f_{Ray,j}
\]

并显式检验 `Ray-first` 与 `strip-first` 的 order effect。若 core 通过，再对 H0/S0 与 H300/S100 各做一对顺序相反的 session：

```text
2 states x 2 sessions x 2 sources = 8
```

TD-C 最大 formal captures 为 16。

### 解释边界

TD-C 不是声称“消除了所有 drift”，而是：

- 让 source order 与 session time 平衡；
- 直接估计 order effect；
- 避免把 50 分钟单方向 chronology 当作 reference shift；
- 为 P6 compatibility 提供稳定 current-session centers。

## 6. 稳定性分析与统计合同

## 6.1 冻结内容不变

下一轮不得修改：

```text
58-feature definition
observer/exposure envelope
trend threshold = 4.0
single-frame dominance threshold = 0.5
covariance method
joint coverage probability / guard
P6 manifold topology
solver objective
```

新 run 只改变 measurement protocol 和状态标签。

## 6.2 推荐的观测符号

令：

\[
f_{s,q,c}(t)\in\mathbb{R}^{58}
\]

表示 source `s`、command/state `q`、independent cycle `c`、elapsed time `t` 的 scale-removed feature。

需要分开估计：

- `within_cycle_settling`：同一 cycle 随 t 的变化；
- `between_cycle_repeatability`：同一 envelope、同一 q、不同 cycle 的 center spread；
- `previous_state_effect`：返回 A 后的 center 与 previous state 的关系；
- `cross_source_difference`：同一 session 的 strip-Ray 差；
- `cross_epoch_difference`：current stable Ray center 与 P6 center 的差。

不能用一个总体 covariance 混合以上五项。

## 6.3 模型仅用于诊断，不用于本轮校正

允许对 settling curve 做以下诊断拟合：

\[
f(t)=f_{\infty}+a\exp(-t/\tau)
\]

或对主要 PCA/feature block 做 monotonic trend fit，但本轮的 steady 判定仍依据冻结 gate 和直接留后时间点，不依据拟合出的 `f_infinity`。原因是 4 个时间点和 3 个 cycle 不足以证明复杂 thermal model。

## 6.4 600 秒后的 extension

以下任一条件触发：

- 300→600 仍有冻结 trend failure；
- 600 秒跨 cycle center 不兼容；
- temperature proxy 仍明显单向变化并与 feature drift 同步；
- return-to-A 在 600 秒仍受 previous state 影响。

状态：

```text
thermal_state_unresolved_beyond_600
```

此时 Planner 只能提交 900/1200 秒 extension PLAN，不能自行把 `t_formal=600` 写入产品合同。

## 7. thermal/time covariate：允许范围与禁用范围

## 7.1 必须记录的 chronology covariate

每张 physical capture 至少增加：

```text
monotonic_timestamp_ns
session_elapsed_s
source_id
state_id / exact command hash
source_on_elapsed_s
state_on_elapsed_s
off_duration_before_s
previous_state_id
previous_state_dwell_s
sequence_index
capture_owner
```

## 7.2 必须记录的 load-history proxy

strip：

- 五通道 raw code；
- code-duty linearized duty；
- `sum_duty`；
- 各通道 duty；
- rolling integrated load proxy at 60/300/900 s。

Ray：

- H/S/INT command/readback；
- fan/power mode；
- rolling INT-on history；
- 由于未知内部多基色功耗，明确标记 `load_proxy_not_electrical_power`。

可定义：

\[
H_{\tau}(t)=\int_{t-\tau}^{t}L_{proxy}(u)\,du
\]

仅用作 history descriptor，不作为真实 junction energy。

## 7.3 温度 covariate

优先增加非侵入式接触温度探头：

```text
ambient_temperature_c
ray_surface_temperature_c
strip_backing_temperature_c
```

要求：

- 探头不遮挡光路、不改变散热结构；
- 记录位置照片/说明和传感器 ID；
- surface temperature 仅是 junction-temperature proxy；
- 无传感器也可执行，但 cold 状态只能叫 `cold_proxy_uninstrumented`。

## 7.4 可接受的统计用途

允许：

1. 作为 state classifier；
2. 检查 feature drift 是否与 time/temp/load 同步；
3. 在同一 frozen envelope 内估计 conditional center 与 repeatability；
4. 形成 future model hypothesis；
5. 在独立 holdout cycle 上验证后，申请版本化 correction model。

禁止：

1. 把确定性 trend 当作零均值随机噪声；
2. 增大 covariance 直到旧候选通过；
3. 用同一 run 同时拟合和验收 thermal correction；
4. 用未来产品无法观测的 covariate构造运行时补偿；
5. 删除不符合拟合曲线的合法帧；
6. 用 surface-temperature plateau 代替 optical-feature stability gate。

## 8. `reference_epoch_shift=false` 的语义纠偏

## 8.1 当前布尔值为什么误导

要判断 epoch shift，需要两个稳定中心：

\[
\Delta_{epoch}=\mu_{Ray,current}-\mu_{Ray,P6}
\]

P7-R1 当前 `mu_Ray,current` 受 chronology/first-frame trend 影响，没有满足 stationarity。此时 shift detector 没有足够条件把结果分类成稳定 epoch shift。`false` 只能表示“未分类为 true”，不能表示“证明 shift 为零”。

## 8.2 新 analyzer schema

建议替换为三轴状态：

```json
{
  "reference_stationarity": "pass|fail",
  "raw_p6_compatibility_gate": "pass|fail|not_tested",
  "interpretable_p6_compatibility": "pass|fail|not_evaluable",
  "reference_shift_class": "none|common|state_dependent|operating_envelope_mismatch|not_identifiable",
  "reference_shift_reason": "...",
  "legacy_reference_epoch_shift": false
}
```

P7-R1 回填为：

```text
reference_stationarity = fail
raw_p6_compatibility_gate = fail
interpretable_p6_compatibility = not_evaluable
reference_shift_class = not_identifiable
reference_shift_reason = within_run_nonstationarity_and_protocol_mismatch
```

## 8.3 后续分类规则

### A. 稳定且兼容 P6

```text
reference_shift_class = none
```

P6 数值中心继续冻结。

### B. 稳定、多个 state 呈一致 shift

```text
reference_shift_class = common
```

先做 Ray-only mini requalification，不可在 P7 run 内静默平移 manifold。

### C. 稳定但 shift 随 Hue/SAT 变化

```text
reference_shift_class = state_dependent
```

说明不是单一 epoch offset；需要扩展 Ray requalification，可能重测 13 direct nodes。

### D. cold/steady 定义不同导致中心不同

```text
reference_shift_class = operating_envelope_mismatch
```

这不是“新自然日 Ray 变了”，而是比较了不同 measurand condition。

### E. 当前会话仍不稳定

```text
reference_shift_class = not_identifiable
```

不得 re-anchor。

## 9. 对 P6 的影响：拓扑冻结，数值中心条件化

## 9.1 不推翻 Gate-5

P7-R1 没有提供证据推翻以下结构结论：

- `full_periodic_2d_HB`；
- SAT0 Hue undefined；
- HSI 与 RGB endpoint 分离；
- Hue 周期；
- 中间 SAT 非仿射。

所以不重拍 106 点，不回退理论 HSL/HSV。

## 9.2 需要重新确认的是 operating envelope compatibility

P6 的 numerical center 依赖其当时的采集 chronology。若 TD-C 得到稳定 current Ray center，但仍不兼容 P6，进入以下分支：

### Mini requalification set

```text
H0/S0
H0/S50, H0/S100
H120/S50, H120/S100
H240/S50, H240/S100
```

共 7 个 Ray-only direct states，在新的 steady protocol 下重复测量。用途：

- 检查 shift 是否近似共同；
- 检查 Hue/SAT 局部几何是否保留；
- 预留 fit/holdout 分离。

### 分支

1. 7 点支持一个预声明的简单 transfer，且 holdout 通过：生成版本化 `reference-epoch-transfer-v1.json`，再回 Advisor；
2. transfer 不成立但 13 个 direct pilot nodes 可稳定：重测 13 nodes，并评估是否只需重建 direct-node centers；
3. 13 nodes 显示曲率/拓扑变化：才考虑重拍完整 106 点；
4. 当前 Ray 仍不稳定：不做任何 re-anchor。

本轮 GUIDE 不预授权 7 点或 13 点实拍；它们是 TD-C 后的决策分支。

| 假设 | 当前支持 | 反证/风险 | 下一实验如何区分 |
| --- | --- | --- | --- |

## 11. 风险与边界

### 11.1 实验时间风险

TD-A/TD-B 包含长时间连续高输出和多次冷却，不能作为一个无人值守长跑。建议拆为多个 named run，每个 run 有独立 physical cap、双 cleanup 和 human authorization。

### 11.2 温度探头的解释风险

外壳/灯带背面温度不是 LED junction temperature。温度可解释 history，但最终 steady gate仍由 optical feature稳定性决定。

### 11.3 P6 与 P7 measurand 不一致风险

若 P6 未记录足够 source-on-time/previous-state 元数据，可能无法把旧点精确归类为 cold 或 steady。此时不能从 current stable center 反推旧 protocol，只能通过 mini requalification 建立新版本。

### 11.4 产品目标风险

选择 steady-state 作为主目标意味着刚点亮的前 60 秒可能不完全匹配 Ray。该限制必须在最终产品文档中显式呈现；未来若用户确实要求启动瞬间复制，应单独研究 transient controller，而不是在本轮偷偷折中 steady LUT。

## 14. 最终研究判断

P7-R1 是一次有效且必要的失败：它证明了工程链路可工作，也证伪了“1 秒 off + 60 秒 on 自动等于 settled repeatability”的隐含假设。下一步不应重新调 solver、删首帧或扩大 uncertainty，而应先定义测量对象的热态。

最小合理路线是：

1. 用 H120/S100 的 3×4 timed curve 找出 cold settling；
2. 用 H120/S50、H0/S0、H300/S100 检验 command-switch 与 previous-state history；
3. 用跨 session 的 Ray/strip AB/BA 顺序平衡建立可解释的 current-session reference center；
4. 只有 Ray 当前 steady center 可辨识后，才讨论 P6 epoch compatibility；
5. 只有 thermal protocol 冻结后，四点 sentinel 才有统计含义。
